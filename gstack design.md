## Problem Statement

AI agents built by developers cannot reliably control websites built for humans. They get stuck on login forms, CAPTCHAs, changing UIs, and authentication flows. Current solutions (Playwright, Puppeteer) require brittle DOM selectors that break on every site update. Developers waste engineering hours maintaining automation scripts instead of building their actual product.

The infrastructure gap: there is no reliable browser automation layer that handles auth, CAPTCHA, dynamic UIs, and anti-bot detection out of the box. Every AI team rebuilds this from scratch.

## Positioning

**This is infrastructure, not an AI agent.** Users bring their own LLM/agent. This platform is the execution engine their agent calls to perform actions on any website.

```
User's AI Agent (their LLM) → This Platform → Any Website
                              ↓
                    Handles: Auth, CAPTCHA, Anti-bot,
                    API replay, DOM control, Vision fallback
```

## Architecture (Hybrid Execution Engine)

### 1. Strategy Router (per action)

Auto-selects the best execution strategy based on what's available:

| Priority | Strategy | When | Speed |
|----------|----------|------|-------|
| 1 | **API Replay** | Intercepted endpoints match intent | 50-200ms |
| 2 | **DOM Control** | APIs unknown, DOM stable | 500ms-2s |
| 3 | **Vision AI** | DOM fails or unavailable (canvas, WebGL, shadow DOM) | 2-5s |

All strategies run through the same Playwright browser instance with stealth plugins.

### 2. Playwright Browser Instance

- Real Chromium with **undetected-playwright** plugins
- Human-like mouse movements, proper headers, TLS fingerprint
- Proxy rotation support
- Session persistence (cookies, localStorage)
- Screenshot capability for vision mode

### 3. Session Recorder (for API discovery)

- CDP network interception during explicit `begin_recording()` / `end_recording()`
- Captures XHR/fetch/WebSocket traffic
- Normalizes URLs: `/invoices/inv_4821` → `/invoices/:param`
- Extracts request/response schemas
- **Passive discovery only** — no crawling, no endpoint enumeration

### 4. Auth Handler

- **Auto-detect login forms** (DOM + vision fallback)
- **Credential vault**: encrypted per-org storage
- **OAuth/SSO flows**: redirect detection, token extraction, refresh token handling
- **MFA/2FA**: TOTP generation, SMS webhook wait, authenticator app support
- **Session refresh**: auto-detect expiry, re-authenticate transparently

### 5. CAPTCHA Resolver

| Type | Method |
|------|--------|
| reCAPTCHA v2 | 2captcha / Anti-Captcha service integration |
| reCAPTCHA v3 | Stealth scoring (human-like behavior) |
| hCaptcha | Solver service |
| Image/text CAPTCHA | Vision model (GPT-4V / Claude) reads and types |
| Per-CAPTCHA retry | Exponential backoff with human-like delays |

### 6. API Graph Extractor

- Builds directed graph from recorded sessions
- Nodes: endpoints with method, URL template, params, auth type
- Edges: sequencing dependencies + data bindings (output of step N → input of step N+1)
- Atomic `graph_version` bump on mutations (prevents stale cache)

### 7. Execution Engine

- Receives **intent + target URL** from user's agent
- Queries API graph for matching sequence
- Falls back to DOM/Vision if no API match
- Handles errors:
  - `401` → trigger re-auth immediately
  - `404` → emit drift alert, mark endpoint stale
  - `429` → respect `Retry-After`, use proxy rotation
  - `5xx` → retry 3x with exponential backoff
  - Bot detection → switch strategy (API → DOM → Vision)
- Returns structured JSON result to user's agent

### 8. Developer SDK

```python
from agentbrowser import AgentBrowser

# Initialize
browser = AgentBrowser(
    api_key="...",
    # Optional: bring your own proxy
    proxy="http://user:pass@host:port"
)

# Configure auth (one-time setup per site)
browser.configure_auth(
    site="https://invoicing.app",
    username="user@example.com",
    password="...",
    mfa_type="totp",  # or "sms", "none"
    mfa_secret="..."
)

# Execute intent — platform handles everything
result = browser.execute(
    site="https://invoicing.app",
    intent="Submit invoice for $1,200 to Acme Corp"
)

# Returns structured result
print(result.status)      # "success" | "error" | "auth_required" | "captcha"
print(result.data)        # { invoice_id: "inv_123", status: "submitted" }
print(result.screenshot)  # base64 screenshot for verification

# Or use streaming for multi-step workflows
for step in browser.execute_stream(intent="..."):
    print(step.action, step.status, step.data)
```

### 9. REST API (for non-Python agents)

```bash
POST /v1/execute
{
  "site": "https://invoicing.app",
  "intent": "Submit invoice for $1,200 to Acme Corp",
  "auth_id": "auth_abc123"
}

Response:
{

  "data": { "invoice_id": "inv_123" },
  "screenshot": "base64...",
  "steps_executed": 4,
  "strategy_used": "api_replay"
}
```

## Feasibility Gate

Before building the platform, validate the core execution loop on 5 real websites:

1. Pick 5 diverse sites: SPA (Notion), server-rendered (Wikipedia), e-commerce (Shopify admin), social (Twitter/X), legacy (random government form)
2. For each, attempt: login → perform one action → logout
3. Measure:
   - Success rate with API replay
   - Success rate with DOM control
   - Success rate with Vision fallback
   - CAPTCHA encounter rate
   - Auth handling success rate
4. **Gate: ≥80% success rate across all 5 sites with the hybrid approach**

If gate fails, identify which sites/strategies are broken and adjust before building platform code.

## Open Questions

1. **Legal/ToS**: Intercepting and replaying APIs without consent — need legal review before production
2. **Anti-bot arms race**: How quickly do detection methods evolve? Can stealth plugins keep up?
3. **CAPTCHA cost**: Solver services add $1-3 per 1000 solves. Impact on unit economics?
4. **First customer**: Which specific AI team needs this today? What are they currently doing?
5. **Vision model cost**: GPT-4V/Claude per-action pricing at scale
